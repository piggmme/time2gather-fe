# 다국어 작업 지침

이 문서는 다국어 작업의 지속적인 운영 기준이다. 문구나 화면을 변경할 때마다 적용하며, 지원 범위나 저장 구조가 바뀌면 이 문서도 함께 갱신한다. 구현 배경은 [globalization.md](globalization.md), 폰트 기준은 [typography.md](typography.md)를 참고한다.

## 기본 원칙

- 사용자가 특정 언어만 수정하라고 명시하지 않으면 문구 변경을 모든 지원 언어에 반영한다. 한국어부터 수정했더라도 다른 언어를 이전 의미로 남기지 않는다.
- 번역은 문구의 역할, 의미, 말투를 유지하면서 각 언어에 자연스럽게 작성한다. 제품에 없는 기능이나 보장을 추가하지 않는다.
- 화면의 상단 문구·제목·설명을 바꾸면 세 항목을 한 묶음으로 확인한다. 예를 들어 서비스 소개 → 핵심 가치 → 이용 방법이라는 역할을 번역에서도 유지한다.
- 신규 사용자 문구를 컴포넌트에 직접 하드코딩하지 않는다. 사용자 입력 내용은 번역하지 않으며 외부 번역 서비스로 전송하지 않는다.
- 기술 검증 통과와 원어민 검수를 구분한다. 원어민 검수 없이 번역 품질을 인증했다고 보고하지 않는다.

## 지원 언어와 수정 위치

지원 언어의 기준은 `src/i18n/config.ts`의 `supportedLocales`/`localeMeta`다. 현재 22개: `en`, `zh-CN`, `hi`, `es`, `ar`, `fr`, `bn`, `pt`, `ru`, `id`, `ur`, `de`, `ja`, `pcm`, `ar-EG`, `mr`, `vi`, `te`, `ha`, `tr`, `ko`, `th`.

| 대상 | 수정 위치 | 주의점 |
| --- | --- | --- |
| 앱 문구 | `src/i18n/locales/{locale}.json` | 모든 언어의 키, 보간 변수, 복수형을 맞춘다. |
| 마케팅 문구 | `src/marketing/copy.ts`, `src/marketing/locales/{locale}.json` | 두 저장 위치를 모두 확인한다. JSON이 같은 언어의 TypeScript 정의를 덮어쓴다. |
| 언어·방향·협상 | `src/i18n/config.ts`, `src/i18n/navigation.ts` | 홈과 안내 페이지는 한국어를 포함해 언어별 고정 주소를 사용한다. 모임·댓글 공유 링크는 받는 사람의 저장 언어 또는 브라우저 언어로 연다. 기존 링크의 명시적 `lang` 값은 존중한다. |
| 폰트 | `src/i18n/fonts.ts`, `docs/typography.md` | 문자 지원, 폴백, 언어별 굵기·줄바꿈을 확인한다. |
| API 오류 | 백엔드 `LocaleConfig`, `messages*.properties`, `ValidationMessages*.properties` | 오류 키와 보간 값, 지원 언어를 프런트엔드와 맞춘다. |

`ar-EG`는 현재 표준 아랍어 문구에 이집트 지역 형식을 적용한다. `pcm`은 별도 피진어 문구를 사용하며 날짜·시간 형식은 `en-NG`를 사용한다. 지원 언어를 추가하면 앱·마케팅·백엔드 리소스와 검증 범위를 함께 확장한다.

## 화면과 날짜·시간

- 아랍어·우르두어 등 RTL 화면의 방향, 혼합 문자, 버튼과 아이콘 배치를 확인한다.
- 긴 번역과 작은 화면에서도 제목·설명·버튼이 잘리거나 가로 스크롤을 만들지 않도록 한다.
- 날짜·시간 표시는 선택한 로케일의 형식을 사용한다. 사용자의 언어에서 거주 국가나 시간대를 추측하지 않는다.
- 모임 시간대와 참가자의 표시 시간대를 구분하고, 번역이나 표시 변경으로 저장된 투표 키를 바꾸지 않는다. 날짜만 있는 투표는 시간대에 따라 날짜를 바꾸지 않는다.
- `{name}` 등 보간 변수와 복수형 분기를 보존하고, 다른 언어의 텍스트가 뜻하지 않게 폴백되지 않는지 확인한다.

## 검증과 완료 기준

1. 지원 언어 목록과 변경한 언어 목록을 비교한다. 마케팅은 TypeScript와 JSON의 최종 합성 결과를 기준으로 확인한다.
2. `npm run check:i18n`, `npm run test:globalization`, 변경한 코드의 ESLint, `npm run build`를 실행한다. 타입에 영향을 주는 수정은 타입 검사도 수행한다.
3. 번역 키 검사는 문구의 최신 의미나 실제 렌더링을 보장하지 않는다. 변경한 화면의 모든 언어에서 실제 상단·제목·설명이 예상 문구와 일치하는지 확인한다.
4. 화면 구조나 문구 길이가 바뀌면 한국어·긴 번역·RTL의 모바일 및 데스크톱 표시를 확인한다. 자동화 결과와 시각 검증 결과를 구분해 기록한다.
5. 배포가 요청되면 후보 버전 확인 후 운영에 반영하고, 운영 도메인의 모든 언어 경로에서 HTTP 상태와 변경 문구를 다시 확인한다. Cloud Run만 갱신하지 말고 Firebase Hosting의 고정 리비전과 정적 파일도 같은 배포에 맞춘다.
6. 배포 기록에 날짜, 대상, 빌드 ID, 리비전, 전체 언어 검증 결과를 남긴다. 미반영 언어, 실패 검사, 미검증 항목이 있으면 정확히 보고한다.

## 현재 랜딩 문구 기준

2026-10-26 합의한 한국어 문구이며, 다른 언어에도 같은 역할과 의미를 적용한다.

- 상단 홍보 문구는 표시하지 않는다. 모든 언어의 홈에 공통으로 적용한다.
