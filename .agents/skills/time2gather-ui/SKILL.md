# Time2Gather UI

내용은 정렬, 제목과 간격으로 묶습니다. 큰 구역이 바뀌는 지점에는 얇은 중립색 구분선을 사용하고, 조작 요소는 옅은 배경으로 구분합니다. 한 화면의 개선을 다른 화면과 분리하지 않습니다. 테두리와 배경을 일괄 제거하지 않고 각 요소의 역할을 먼저 확인합니다.

## 표현 기준

| 역할 | 적용 방식 | 예시 |
| --- | --- | --- |
| 큰 구역의 경계 | 제목과 1px 중립색 구분선, 선과 내용 사이 24px 전후 간격. 모바일은 가로선, 나란한 데스크톱 보조 영역은 세로선 | 결과와 약속 관리, 댓글, 입력과 다음 단계 버튼, 관리자 목록, 안내 페이지의 장 구분 |
| 읽는 내용 | 투명 배경, 외곽 테두리와 그림자 없음. 제목과 간격으로 묶기 | 약속 설명, 참여자, 안내, 통계, 소개와 FAQ |
| 누르거나 선택하는 단위 | 옅은 중립 배경 또는 얇은 중립색 테두리, 기본 12px 모서리, 그림자 없음. 선택 시 색과 표시를 함께 사용 | 일정 후보, 약속 목록 링크, 약속 종류, 보조 버튼 |
| 입력 | 입력 범위를 알 수 있는 얇은 테두리와 명확한 포커스 유지 | 이름, 검색, 댓글, 시간 입력 |
| 밀도 높은 정보 | 관계를 읽는 데 필요한 선 유지 | 달력 격자, 시간표, 관리자 표, 댓글의 답글 연결 |
| 떠 있는 요소 | 불투명 배경과 기존 공통 그림자 사용 | 다이얼로그, 메뉴, 툴팁, 토스트, 모바일 메뉴 |

- 여백만으로 모든 구역을 나누지 않습니다. 서로 다른 역할의 구역은 제목과 약한 선으로 구별합니다. 이름, 아이콘, 짧은 설명마다 구분선을 추가하지 않습니다.
- 내용을 감싸는 카드 안에 카드나 이름 캡슐을 반복하지 않습니다. 참여자 이름은 아바타와 이름의 간격으로 구분합니다.
- 같은 이유의 경계를 테두리, 배경, 그림자로 중복 강조하지 않습니다.
- 안내 전체에 회색 배경을 칠해 버튼처럼 보이게 하지 않습니다. 클릭 가능한 단위의 범위와 실제 클릭 영역을 맞춥니다.
- 읽기 전용 내용에는 떠오르는 호버 효과를 넣지 않습니다. 조작 요소의 호버는 배경과 글자색으로 표시합니다.
- 선택, 포커스, 오류, 비활성, 확정 상태의 구분을 지우지 않습니다. 색만으로 선택 상태를 전달하지 않습니다.
- 글자 크기를 줄여 여백을 확보하지 않습니다. 페이지 안쪽 정렬선을 맞추고 관련 항목 사이 8–16px, 서로 다른 구역 사이 24–32px를 먼저 사용합니다. 넓은 화면의 큰 구역은 48px까지 사용할 수 있습니다.
- 모든 구역 사이를 똑같이 넓히지 않습니다. 제목과 설명, 이름과 아바타, 입력과 안내는 가까이 유지합니다.

## 구현 위치

- [공통 면 스타일](../../../src/styles/surfaces.scss): `surfaces.content`, `surfaces.action`, `surfaces.person`, `surfaces.section-start`, `surfaces.section-side` 믹스인과 배경, 모서리, 간격 토큰.
- [기본 토큰](../../../src/styles/variables.scss): 브랜드 색, 글자 크기, 간격, 상태 색, 떠 있는 요소의 그림자.
- [공통 버튼](../../../src/components/Button/Button.module.scss), [입력](../../../src/components/Input/Input.module.scss), [선택](../../../src/components/Select/Select.module.scss), [다이얼로그](../../../src/components/Dialog/Dialog.module.scss)를 우선 사용합니다.
- 페이지별 클래스 이름을 전역 CSS에서 묶어 강제 덮어쓰지 않습니다. 해당 컴포넌트에서 믹스인을 적용하고 오래된 장식 선언을 제거합니다. 실제 조작 범위의 패딩과 배치는 컴포넌트가 관리합니다.

```scss
@use '../../styles/surfaces.scss' as surfaces;

.information {
  @include surfaces.content;
  padding-block: 12px;
}

.selectableOption {
  @include surfaces.action;
  // 기존 선택 상태와 키보드 포커스 선언을 유지합니다.
}
```

## 문구와 정보 위계

- 영어권 사용성은 명확한 행동 라벨, 문장형 대소문자, 날짜와 시간대의 명시를 우선합니다. 특정 지역 전체가 한 가지 미감을 선호한다고 가정하지 않습니다.
- 보조 동작은 약속 관리처럼 역할을 드러내는 제목으로 묶습니다. 새로운 약속을 만드는 안내는 본래 약속보다 작고 간결하게 표시합니다.
- 날짜 표기는 각 로케일을 따릅니다. 북미를 겨냥한다는 이유로 다른 언어까지 미국식 숫자 날짜로 바꾸거나 표시 시간대를 고정하지 않습니다.

## 작업 범위 확인

먼저 변경하는 컴포넌트의 사용 위치를 찾습니다. 버튼이나 공통 면 스타일을 바꾸면 아래의 영향을 함께 확인합니다.

- 홈과 소개, 문의, 약관, 개인정보 페이지
- 약속 종류, 제목, 날짜, 시간, 장소와 이름 입력 단계
- 날짜 투표와 시간 투표, 장소 투표, 투표 날짜 수정
- 결과, 달력, 장소, 참여자, 확정 상태와 캘린더 내보내기
- 댓글 작성, 답글, 이름 변경, 내 약속과 검색
- 관리자 로그인, 통계와 목록, 공통 메뉴와 다이얼로그

변경과 무관한 기능이나 저장 데이터의 의미를 바꾸지 않습니다. 새 화면도 위 역할 구분을 따릅니다.

## 검증

[다국어 지침](../../../docs/i18n-guidelines.md)과 저장소 `AGENTS.md`를 따릅니다. 문구를 바꾸지 않은 스타일 수정도 긴 번역과 RTL에서 배치를 확인합니다.

- 320–390px 모바일과 1280px 이상 데스크톱에서 한국어, 긴 번역 언어, RTL을 실제 렌더링합니다. 논리 방향 속성을 사용하고 긴 이름, 여러 참여자, 빈 상태를 확인합니다.
- 달력 선택과 드래그, 후보 펼치기, 입력과 키보드 포커스, 다이얼로그 스크롤과 하단 버튼을 확인합니다. 모바일 조작 영역은 최소 44px를 기준으로 합니다.
- 공통 변경은 사용 화면 전체를 점검합니다. 지원 언어 수, 테스트한 화면과 상태, 실제 브라우저를 기록하고 미검증 범위를 구분합니다.
- 결과에는 예시 데이터를 사용한 실제 변경 화면을 포함합니다. 시안은 실제 검증 결과와 구분합니다.
- 배포는 요청받았을 때 수행합니다. 배포 요청이 있으면 현재 운영 소스와 비교해 관련 변경만 포함하고, Cloud Run 리비전과 Firebase Hosting의 정적 파일 및 고정 태그를 맞춥니다. 전체 언어의 운영 응답과 배포된 스타일을 확인합니다.
