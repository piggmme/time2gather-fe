# Time2Gather 푸시 전 검증

실제 릴리스 소스에서 로컬 검사를 통과한 뒤 한 번에 푸시합니다. 이 스킬은 기존 작업의 푸시나 배포 권한을 확대하지 않습니다.

## 소스와 검사 기준

- 프런트엔드와 백엔드의 AGENTS.md를 읽고 관련 없는 변경을 보존합니다. 기본 작업 트리에는 미배포 변경이 많을 수 있으므로 실제 운영 소스와 변경 범위를 먼저 확인합니다.
- 필요하면 검증된 릴리스 소스에서 별도 worktree를 만듭니다. 기존 작업 폴더나 main의 오래된 소스를 운영 소스로 간주하지 않습니다.
- 검사 목록은 프런트엔드의 `scripts/frontend-checks.json` 한 곳에서 관리합니다. 로컬과 CI 모두 `scripts/frontend_preflight.py run`을 실행합니다. workflow에 검사 명령과 파일 목록을 다시 복사하지 않습니다.
- `baseRevision`은 검증된 기준 커밋입니다. 기존 CI 필수 파일과 이 커밋 이후 변경된 JS, TS, Astro 파일에 ESLint를 적용합니다. 기준을 바꾸면 계획 파일에 반영해 로컬과 CI의 검사 범위를 맞춥니다. 저장소 전체 lint를 수행한 것으로 보고하지 않습니다.

## 푸시 순서

1. 테스트 문제를 재현하고 원인을 고칩니다. 반복 실행으로 우연히 통과시키거나 단언, 언어, 필수 검사를 제거하지 않습니다. 추가한 테스트와 검사 대상 파일이 실제 소스에 포함됐는지 확인합니다.
2. 변경 범위를 검토하고 로컬 커밋을 만듭니다. 이 시점에는 원격 작업이 발생하지 않습니다.
3. CI와 같은 Node.js 20에서 `python3 scripts/frontend_preflight.py run`을 실행합니다. 패키지 스크립트는 `pnpm preflight`입니다. 실행 도구가 다른 pnpm 버전을 쓰면 `corepack pnpm@10.23.0 preflight`를 사용합니다.
4. 스크립트가 고정 lockfile 설치, ESLint, 타입, 22개 언어, 배포 도구, 빌드와 기존 브라우저 회귀 검사를 순서대로 실행합니다. `CI=true`, 색상 로그를 적용합니다. 각 검사 로그는 `.preflight`에 남습니다. 첫 실패에서 중단하고 검사 기록을 발급하지 않습니다.
5. `python3 scripts/frontend_preflight.py verify`로 현재 커밋의 검사 기록을 확인합니다. 소스가 바뀌면 커밋 후 전체 검사를 다시 실행합니다. 검사 중에도 소스가 바뀌면 성공으로 처리하지 않습니다.
6. 푸시가 승인된 작업에서만 푸시합니다. `python3 scripts/frontend_preflight.py install-hook`으로 설치한 pre-push hook은 검사 기록이 없거나 커밋이 다르면 푸시를 막습니다. `--no-verify`나 hook 해제로 우회하지 않습니다.

## 테스트와 이미지 빌드

- 서버 준비 여부는 `scripts/wait-for-server.mjs`의 HTTP 응답으로 판단합니다. 색상 로그 문구를 파싱하지 않습니다. 모임 생성과 분석 이벤트 검사는 빌드한 서버에서 수행해 개발 툴바와 HMR 간섭을 피합니다.
- 브라우저 검사는 로컬 fixture를 사용합니다. 실패한 제품 동작과 잘못된 테스트 조작을 구분하고 실제 원인에 맞춰 고칩니다. 환경이나 브라우저 누락을 조용히 건너뛰지 않습니다.
- 결과 파일은 `.preflight/evidence` 안에 모읍니다. GitHub artifact 경로에 `../`를 넣지 않습니다.
- 일반 기능 브랜치 CI는 검증과 dist 업로드를 수행합니다. 이미지 빌드는 main, release 브랜치 또는 `publish_image=true`로 요청한 실행에서 검증 성공 후에만 수행합니다. 릴리스가 필요한 작업에서 기존 검증 dist와 manifest를 재사용하고 후보에서 확인한 digest를 운영에 재사용합니다.
- 실패한 CI를 바로 재실행하거나 Cloud Build에 제출하지 않습니다. 먼저 로컬에서 원인을 재현하고 고친 소스의 공통 검사를 통과시킵니다. 비용 절감액은 측정 없이 단정하지 않습니다.

완료 보고에는 검사한 커밋, 성공한 검사, 푸시나 배포 여부와 미검증 환경만 간결하게 남깁니다.
